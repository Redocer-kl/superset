# Custom Apache Superset Production Build

Репозиторий содержит кастомизированную сборку Apache Superset (v6.1.0) с измененным брендингом, скорректированным роутингом и предустановленным драйвером для ClickHouse.

## Выполненные задачи (Pull Requests)

Вся работа велась по методологии Git Flow. В ветку `main` последовательно влиты изолированные Pull Request'ы для каждого шага:

1. `feature/clickhouse-driver` — Интеграция драйвера `clickhouse-connect`.
2. `feature/favicon` — Замена стандартного фавикона приложения.
3. `feature/branding` — Полное обновление пакета логотипов во фронтенде.
4. `feature/uichanges` — Удаление надписи "Powered by Apache Superset" из UI меню.
5. `feature/custom-homepage` — Настройка дефолтного дашборда как стартовой страницы (без 302 редиректа, доступно для ролей Alpha/Gamma).
6. `feature/remove-url-prefix` — Глобальное исключение префикса `/superset/` из URL-роутинга бэкенда и фронтенда.

## Инструкция по запуску (Имитация Production)

### 1. Сборка Docker-образа

Сборка кастомного образа с обновленными ассетами фронтенда и бэкенд-зависимостями выполняется без использования кэша для гарантии применения изменений:

```bash
docker compose build --no-cache
```

### 2. Запуск Superset

Запуск всей инфраструктуры (Superset, база данных метаданных, Redis для кэширования) в бэкграунде:

```bash
docker compose up -d
```

При первом запуске контейнер автоматически выполнит скрипт инициализации (`docker-init.sh`): накатит миграции БД, создаст администратора, загрузит демонстрационные датасеты и принудительно опубликует стартовый дашборд (ID: 1) для непривилегированных пользователей.

После запуска приложение доступно напрямую по адресу: `http://localhost:8088/welcome/`

## Что еще необходимо изменить для реального Production?

Для перевода текущей конфигурации из тестового production-окружения в реальный безопасный продакшн необходимо внедрить следующие изменения:

### Безопасность ключей и паролей

- Заменить дефолтный `SECRET_KEY` во Flask (`CHANGE_ME_SECRET_KEY`) на стойкую сгенерированную строку (например, через `openssl rand -base64 42`).
- Вынести все пароли БД, доступы к Redis и учетные данные администратора из `docker-compose.yml` в изолированный файл `.env`, добавленный в `.gitignore`, либо использовать Secret Manager.

### Бэкенд базы данных метаданных

- Заменить стандартную базу метаданных (PostgreSQL/MySQL внутри контейнера) на отказоустойчивый внешний кластер БД (например, AWS RDS или управляемый PostgreSQL) с настроенным ежедневным резервным копированием (снапшотами).

### Логирование и мониторинг

- Настроить интеграцию с внешними системами сбора логов и метрик (Prometheus + Grafana, ELK Stack или Datadog) для отслеживания долгоживущих аналитических запросов и загрузки CPU/Memory Celery-воркеров.

### Кеширование и масштабирование

- Настроить более агрессивное кэширование результатов запросов к чартам (внутри Redis) для снижения нагрузки на ClickHouse и другие целевые источники данных.
- Вынести Celery-воркеры на отдельные инстансы для параллелизации тяжелых выгрузок отчетов и асинхронных запросов в SQL Lab.

### Сетевой контур и SSL

- Закрыть прямой доступ к порту 8088.
- Развернуть Superset за Reverse Proxy (Nginx / Traefik) с обязательной настройкой SSL (HTTPS) сертификатов (Let's Encrypt) и HTTP Strict Transport Security (HSTS).
